# Contract — The Folder Index

`<artifact-root>/impact-analysis/README.md`. Created on demand, rewritten on every run.

## Why it is not an artifact

Principle VII allows exactly one artifact type per folder. The index is navigation, not an artifact: it carries
no sequence number, it describes the folder rather than a feature, and nobody takes it to a stakeholder. That is
what lets it sit beside the numbered documents without breaking the rule.

## Shape

```markdown
# Impact analyses

Generated by `speckit.spectra.impact`. One row per analysis, newest last.

| id | Title | Status | Impact | Generated | Supersedes | Superseded by |
|----|-------|--------|--------|-----------|------------|---------------|
| [001](001-cart-abandonment.md) | Cart abandonment recovery | superseded | high | 2026-04-11 | — | 003 |
| [002](002-guest-checkout.md) | Guest checkout | approved | medium | 2026-05-02 | — | — |
| [003](003-cart-abandonment-recovery.md) | Cart abandonment recovery | draft | high | 2026-09-03 | 001 | — |
```

| Column | Source | Notes |
|---|---|---|
| id | front matter `id` | Linked to the file |
| Title | front matter `title` | |
| Status | front matter `status` | **Re-read every run** |
| Impact | front matter `impact` | |
| Generated | front matter `generated` | Date is enough in the table; the document carries the full timestamp |
| Supersedes | front matter `supersedes` | `—` when null |
| Superseded by | front matter `superseded_by` | `—` when null |

## The refresh rule

On every run, in this order (FR-056):

1. Read the front matter of every `*.md` in the folder except the index itself.
2. Rebuild every existing row from what was read.
3. Append the row for the document just written.
4. Write the index once, as part of the run's final write.

**No document is modified in order to do this.** The index is derived; the documents are the source of truth.

**Why derive rather than append-only.** Approval is manual: a human edits a document's front matter to
`approved` or `rejected` after taking the draft to stakeholders (FR-053a). An append-only index would carry the
status each document had at the moment it was written, so it would be wrong about the most important column
within a day of the first approval — and being right about which analysis is current is the whole reason the
index exists.

## Edge conditions

| Condition | Behaviour |
|---|---|
| Folder has no index | Create it with the header and all rows |
| A document has unparseable front matter | Keep its row, mark the unreadable fields `?`, note it once in the run report — do not skip the row and do not edit the document |
| A document was deleted since the last run | Its row disappears, because rows are derived from files present |
| Numbering has a gap | Rows reflect what exists; the next id is still highest-plus-one (FR-050) |
| A human edited the index by hand | Overwritten. The documents are authoritative; a hand-edit to the index is not a place to record anything |
| The run is interrupted before the final write | Index unchanged (FR-051a) |
