# Contract: Proposal File Format & Handoff

Defines the on-disk format of `.specify/memory/domain-analysis.md` and the handoff contract
`/speckit-constitution` relies on. This is the load-bearing interface of the feature.

## File skeleton

```markdown
# Domain Analysis — Guardrail Proposals

> Generated by speckit.domain-analyzer.analyze. Review below: check `- [x]` the guardrails
> you want, edit wording freely, leave unwanted ones unchecked. Then run
> `/speckit-constitution` referencing this file. Nothing here is adopted until you check it.

## Inferred Domain

<one-paragraph domain summary + evidence basis>

<optional: compliance add-on recommendation, advisory only>

## <Target Constitution Section A>

- [ ] <Guardrail statement, declarative/testable, MUST/SHOULD + rationale>
  - id: `da-<section-slug>-<hash>`
  - section: <Target Constitution Section A>
  - evidence: `path/to/file.ext` — "<optional short quote or line ref>"
  - confidence: High | Medium | Low
  - status: new

## <Target Constitution Section B>

- [ ] <statement>
  - id: `da-...`
  - section: <Target Constitution Section B>
  - evidence: `path/a` ; `path/b`
  - confidence: Medium
  - status: amends: <Principle name/number>

## New in this run (YYYY-MM-DD)

<!-- appended only on re-run; contains candidates whose id was not already present -->
- [ ] <new candidate>
  - id: `da-...`
  - ...
```

## Candidate block rules

1. **Checkbox line is the anchor and selection signal.** Exactly one `- [ ]` (unselected) or
   `- [x]` (selected) line per candidate, carrying the guardrail statement. A fresh file MUST
   render every candidate as `- [ ]` (FR-005, SC-006).
2. **Metadata is indented beneath the checkbox** as a nested bullet list with these keys, in
   order: `id`, `section`, `evidence`, `confidence`, `status`. (data-model.md → Candidate.)
3. **`id`** is the content-derived stable ID (research D5). Format `da-<section-slug>-<hash>`.
4. **`evidence`** lists one or more `path` entries (SC-002 requires ≥1), each optionally
   followed by `— "<quote>"` or a line reference. Multiple refs separated by ` ; `.
5. **`confidence`** ∈ {High, Medium, Low}.
6. **`status`** is `new`, or `amends: <Principle>` naming the constitution principle the
   candidate would change (FR-009, D8).
7. **Grouping**: candidates are grouped under `##` headings by target section (FR-013).

## Handoff contract (consumed by `/speckit-constitution`)

- **Selected set** = every candidate whose checkbox is `- [x]`. Only these are adopted
  (FR-008, US2). `- [ ]` candidates are ignored.
- The **statement text as it appears on the checkbox line** is the adopted wording — SME edits
  to that text flow through verbatim (US2 acceptance #2).
- A candidate's `section` field tells the constitution agent where to place it; `status:
  amends:` tells it to modify the named principle rather than add a new one.
- If **no** candidate is checked, the handoff yields zero guardrails (US2 acceptance #3).

## Re-run preservation contract (research D7)

- Existing candidate blocks (including checkbox state, edited statement text, and their order)
  MUST be reproduced unchanged. The command MUST NOT reorder or rewrite them (FR-011, SC-005).
- Only candidates whose `id` is absent from the existing file are appended, under a
  `## New in this run (YYYY-MM-DD)` heading (Journey 3 — distinguishable).
- If no new candidates are found, no duplicate blocks are added (US3 acceptance #3).
